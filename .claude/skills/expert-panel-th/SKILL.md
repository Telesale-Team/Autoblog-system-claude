# Skill: Expert Panel (ภาษาไทย)

ประกอบคณะกรรมการตามชนิดงานและกลุ่มลูกค้า ให้คะแนน วนแก้จนผ่าน แล้วเก็บผลลง DB
เพื่อให้เจ้าของกดอนุมัติที่ `/owner/content-quality/`

> ที่มาแนวคิด: `content-ops/SKILL.md` ของ ai-marketing-skills (MIT)
> **ยืมวิธีคิด ไม่ได้ยืมรายการคำ** — ตัวตรวจ AI-slop ของเขาเป็นภาษาอังกฤษล้วน ใช้กับเราไม่ได้
> ของเราอ่านรายการจาก `marketing.SlopPattern` ใน DB แทน

## เมื่อไหร่ใช้
- ก่อน publish บทความทุกชิ้นที่สำคัญ (ไม่ต้องใช้กับทุกชิ้น — กินโทเคน)
- ผู้ใช้ขอให้ตรวจคุณภาพ / ให้คะแนน / เทียบหลายเวอร์ชัน
- Content Writer เขียนเสร็จแล้วอยากรู้ว่าผ่านหรือยังก่อนส่ง

## Input ที่ต้องการ

```yaml
article_id: 47                    # id ใน blog.Article — บังคับ ใช้ผูกคะแนน
segment: "beauty_wellness"        # กลุ่มลูกค้า ใช้ประกอบกรรมการและตรวจโทน
rubric: "content-quality"         # ดูตารางใน Step 2
```

ถ้ายังไม่มีบทความใน DB ให้ publish เป็น draft ก่อน (ตามกฎ draft only)

---

## Step 1: อ่านของที่ต้องใช้ก่อนเสมอ

```
venv\Scripts\python.exe scripts/expert_panel.py --prepare <article_id> --segment <key>
```

สคริปต์นี้จะคืน:
- เนื้อบทความ (แปลง Markdown แล้ว)
- โปรไฟล์ 5 มิติของ segment นั้น (โทนที่ควรเป็น + แหล่งอ้างอิงที่ควรมี)
- **รายการ AI-slop ที่ใช้งานอยู่ทั้งหมดจาก DB**
- ผลการค้นหา slop แบบตรงตัวที่เจอในบทความ พร้อมตำแหน่ง

**ห้ามใช้รายการ slop จากความจำ** — รายการนี้โตขึ้นเรื่อย ๆ เจ้าของเพิ่มเองได้ที่หน้าเว็บ

---

## Step 2: เลือกเกณฑ์ให้คะแนน

| ชนิดงาน | ไฟล์เกณฑ์ |
|---|---|
| บทความ บล็อก โพสต์โซเชียล จดหมายข่าว | `references/rubric-content.md` |
| กลยุทธ์ ข้อเสนอแนะ บทวิเคราะห์ | `references/rubric-strategy.md` |
| หน้าขาย โฆษณา CTA | `references/rubric-conversion.md` |
| Diagram infographic ภาพปก | `references/rubric-visual.md` |
| บทเรียน คอร์ส คู่มือ | `references/rubric-teaching.md` |

อ่านไฟล์เกณฑ์จริงก่อนให้คะแนน อย่าให้คะแนนจากความรู้สึก

---

## Step 3: ประกอบคณะกรรมการ 7-10 คน

**สองคนนี้ต้องมีทุกครั้ง ไม่มีข้อยกเว้น:**

| กรรมการ | น้ำหนัก | ตรวจอะไร |
|---|---|---|
| **ตัวตรวจ AI-slop** | **1.5** | ใช้รายการจาก DB ทั้งหมด หักคะแนนตาม `penalty` ของแต่ละรายการ |
| **ตัวตรวจโทนตาม segment** | 1.0 | โทนตรงกับ `tone` ในโปรไฟล์ไหม สรรพนามถูกไหม นามปากกาลงชื่อหรือยัง |

**แล้วเติมอีก 5-8 คนตามงาน** เช่น
- บทความคลินิก → เพิ่ม ผู้ตรวจ PDPA, ผู้ตรวจความถูกต้องทางการแพทย์
- บทความร้านค้าออนไลน์ → เพิ่ม ผู้เชี่ยวชาญ Shopee/Lazada, ผู้ตรวจ FOMO ว่าเกินไปไหม
- บทเรียน Python → เพิ่ม ผู้ตรวจว่าโค้ดรันได้จริง, ผู้ตรวจว่าคนเริ่มต้นตามทัน
- ทุกงาน → ผู้ตรวจ SEO, ผู้ตรวจว่ามีแหล่งอ้างอิงจริง, ผู้อ่านตัวแทนกลุ่มเป้าหมาย

**เกิน 10 คนให้ยุบรวมที่ซ้ำกัน** — กรรมการเยอะไปคะแนนจะเฉลี่ยจนไม่มีใครได้ต่ำกว่า 85

---

## Step 4: ให้คะแนน แล้ววนแก้จนถึง 90

**เกณฑ์ผ่าน 90 · วนได้สูงสุด 3 รอบ**

แต่ละรอบต้องออกมาแบบนี้:

```
## รอบที่ N — คะแนน XX/100

| กรรมการ | คะแนน | น้ำหนัก | เหตุผลสั้น ๆ |
|---|---|---|---|
| ตัวตรวจ AI-slop | 72 | 1.5 | เจอ "ในยุคดิจิทัล..." (-10) และ "ครบวงจร" (-5) |
| ... | ... | 1.0 | ... |

คะแนนรวมถ่วงน้ำหนัก: XX
จุดอ่อน 3 อันดับแรก: 1... 2... 3...
สิ่งที่แก้ในรอบนี้: ...
```

**กติกา:**
- ให้คะแนนตามจริง **ห้ามปัดขึ้นให้ถึง 90** ถ้าไม่ถึงก็คือไม่ถึง
- รวมคะแนนแบบถ่วงน้ำหนัก: `sum(คะแนน × น้ำหนัก) / sum(น้ำหนัก)`
- ต่ำกว่า 90 → หาจุดอ่อน 3 อันดับแรก → แก้ → รอบถัดไป
- ครบ 3 รอบยังไม่ถึง 90 → ส่งเวอร์ชันที่ดีที่สุดพร้อมบอกตรง ๆ ว่าติดอะไร
- **แสดงทุกรอบ** อย่าโชว์แค่รอบสุดท้าย เส้นทางการแก้คือของมีค่า

---

## Step 5: บันทึกผลลง DB

```
venv\Scripts\python.exe scripts/expert_panel.py --save <article_id> --json <ไฟล์ผลลัพธ์.json>
```

รูปแบบ JSON:
```json
{
  "article_id": 47,
  "segment": "beauty_wellness",
  "rubric": "content-quality",
  "rounds": [
    {"round_no": 1, "experts": [
      {"expert": "ตัวตรวจ AI-slop", "lens": "อ่านออกไหมว่า AI เขียน",
       "score": 72, "weight": 1.5, "feedback": "เจอ 3 รายการ"}
    ]}
  ],
  "weaknesses": "ยังไม่มีตัวเลขอ้างอิงใน H2 ที่สอง",
  "slop_hits": "ในยุคดิจิทัลที่เปลี่ยนแปลงอย่างรวดเร็ว (-10)"
}
```

สคริปต์จะคิดคะแนนรวมให้เอง นับ `hit_count` ของ slop ที่เจอ และตั้งสถานะ
`passed` / `needs_work` ตามเกณฑ์

---

## Step 6: บอกผู้ใช้ว่าต้องทำอะไรต่อ

```
ตรวจเสร็จแล้ว — [คะแนน]/100 ([ผ่าน/ยังไม่ผ่าน]) วนไป N รอบ
ดูรายละเอียดและกดอนุมัติได้ที่ /owner/content-quality/<id>/
```

**ห้าม publish เอง** แม้คะแนนจะเต็ม 100 — คะแนนบอกว่า "ดีพอ"
แต่การอนุมัติบอกว่า "เจ้าของยอมให้เผยแพร่" สองอย่างนี้ไม่ใช่เรื่องเดียวกัน
(ดู `feedback_publish_draft_only`)

---

## Anti-pattern
- ❌ **ปัดคะแนนขึ้นให้ถึง 90** — ทำให้ระบบทั้งหมดไร้ความหมาย
- ❌ ใช้รายการ AI-slop จากความจำแทนที่จะอ่านจาก DB
- ❌ โชว์แค่คะแนนสุดท้าย ไม่โชว์เส้นทางการแก้
- ❌ ตั้งกรรมการเกิน 10 คน — คะแนนจะเฉลี่ยจนไม่มีใครตก
- ❌ ตั้งกรรมการที่ไม่เกี่ยวกับงาน เช่น เอาผู้ตรวจ PDPA มาตรวจบทความร้านค้าออนไลน์
- ❌ **publish เองหลังคะแนนผ่าน** — ต้องรอเจ้าของกดอนุมัติเสมอ
- ❌ ตรวจโดยไม่รู้ segment — โทนที่ถูกของสปากับของคลินิกคนละเรื่องกัน
