## 0. จุดที่ต้องแก้ก่อนใช้งานได้ — งานทั้งสองชิ้นยังไม่ตรงมติ QF-1

มติ QF-1 ที่เจ้าของเคาะ 27 ส.ค. บอกว่า V1-V4 พังเพราะเป็น **"หน้าเดียวจบ" ไม่แยกบทบาท** ให้ทำ V5
ที่ **แยกบทบาทหน้า**: หน้าโฆษณา (ปิดทางออก เหลือ CTA เดียว) → หน้าขาย (SEO ครบ ราคา 3 tier) → ตัวลองเล่น → ฟอร์ม → ContactLead

แต่ทั้งสองเอกสารที่ทีมส่งมาเมื่อวาน **ยังออกแบบเป็นหน้าเดียวยาวทั้งคู่**:
- `queueflow_salepage_structure.md` เสนอยุบ V1-V4 เหลือ "V1 ปรับปรุง" หน้าเดียว 11 section (Hero → Proof → Pain → Flow → ... → FAQ → CTA)
- `queueflow_salepage_message.md` เสนอ V3 ใหม่หน้าเดียว 9 section เช่นกัน (Hero → Proof → Pain → ... → FAQ → CTA)

**นี่ไม่ใช่ของเสีย — เป็นวัตถุดิบที่ใช้ได้เกือบทั้งหมด** ทั้งสองไฟล์ทำการบ้านมาแล้ว (screenshot จริง, ราคา, ตารางเทียบคู่แข่ง, FAQ, ข้อห้าม PDPA/Legal) งานของทีมวันนี้คือ **ตัดแบ่ง** เนื้อหาที่มีอยู่แล้วให้ลงในหน้าคนละใบตามบทบาท ไม่ใช่คิดเนื้อหาใหม่ทั้งหมด

## 1. โครงชุดหน้า V5 (4 จุด)

```
โฆษณา/โพสต์/DM → [หน้า A: โฆษณา] → กดปุ่มเดียว → [หน้า B: หน้าขาย] → กด "ลองเล่นจริง"
                                                          ↓                    ↓
                                                     [หน้า D: ฟอร์ม]   [หน้า C: ตัวลองเล่น]
                                                          ↓                    ↓ (กดกลับมาสมัคร)
                                                    ContactLead ← ── ── ── ── ┘
```

### หน้า A — โฆษณา (Landing, ปิดทางออก)
**เป้าหมายเดียว:** คนที่คลิกจากแอด/โพสต์/DM กดปุ่มเดียวไปต่อ ไม่มีทางออกอื่น ไม่มี navbar เว็บหลัก ไม่มีลิงก์เข้า `/services/` อื่น
**เนื้อหา (ดึงจาก message.md ส่วน S1 Hero + สามประโยคแรกในหัวข้อ 5):**
- พาดหัว: "ให้ลูกค้าจองคิวเองได้ 24 ชั่วโมง บนเว็บของร้านคุณเอง — จ่ายครั้งเดียว ไม่มีรายเดือนตลอดชีพ"
- 3 USP chip (เป็นเจ้าของ / ลูกค้าเป็นของร้าน / ไม่มีค่าคอม)
- screenshot จริง 1 ภาพในกรอบ browser (`queueflow-demo-home.webp`)
- **CTA เดียว:** "ดูรายละเอียดทั้งหมด" → ไปหน้า B เท่านั้น (ไม่มีปุ่มคู่ขนานแบบที่ message.md เสนอไว้ — กติกาหน้าโฆษณาคือ CTA เดียวจริงๆ)
- ไม่มี FAQ ไม่มีราคา ไม่มีตารางเทียบ — สั้นที่สุดเท่าที่ทำได้ ต่ำกว่า 1 จอมือถือถ้าเป็นไปได้

### หน้า B — หน้าขาย (SEO ครบ, ราคา 3 tier)
**นี่คือหน้าที่ทั้งสองเอกสารเมื่อวานออกแบบไว้แล้ว — ใช้ของเดิมเกือบทั้งหมด**
- โครง 11 section จาก `queueflow_salepage_structure.md` หัวข้อ 3 (Sticky topbar → Hero → Proof → Pain → Flow → ของจริง 3 กลุ่ม → 3 เสาหลัก → ตารางเทียบ 5 คอลัมน์ → หลังบ้านครบแค่ไหน → ราคา 3 tier → FAQ → CTA+ฟอร์ม)
- สารและ copy เต็มจาก `queueflow_salepage_message.md` หัวข้อ 1 (7 ฟีเจอร์เด็ด), หัวข้อ 3 (โครง 9 section — merge เข้ากับ 11 section ของลอย), หัวข้อ 4 (ราคา + TCO)
- **ราคา:** ใช้ตัวเลขที่ผ่าน Money Manager แล้วจริง (roadmap.py เฟส 5) — Starter ฿9,900+฿990/ด. | Pro ฿19,900+฿1,990/ด. | Multi ฿39,900+฿3,990/ด. **ไม่ใช่** ตัวเลข "ขายขาด 12,900/19,900/29,900" ที่ message.md เสนอใหม่ — นั่นคือข้อเสนอเปลี่ยนโครงสร้างราคาทั้งระบบ ต้องกลับไปผ่าน Money Manager อนุมัติใหม่ก่อน ยังไม่ใช่มติ (ดู DECISION ใหม่ข้อ 3 ด้านล่าง)
- SEO block เต็ม (title/meta/OG) ตามที่ V1 มีอยู่แล้ว — extends `base_public.html` เหมือนเดิม ตามข้อเสนอของลอยข้อ 1
- **CTA คู่ขนาน 2 ปุ่ม อนุญาตในหน้านี้เท่านั้น:** "ลองเล่นระบบจริง" (→ หน้า C) และ "ทัก LINE / กรอกฟอร์ม" (→ หน้า D)

### หน้า C — ตัวลองเล่น
มีอยู่แล้ว: `booking.noodee-bootbiz.com` (เว็บทดลอง + ข้อมูลตัวอย่าง 84 คิว, roadmap เฟส 5 DONE)
**งานที่เหลือ:** ใส่แถบเล็กด้านบนของเว็บทดลอง "สนใจระบบนี้ให้ร้านคุณ? กลับไปดูราคา" ลิงก์กลับไปหน้า B — ตอนนี้ยังไม่มีทางกลับ (เว็บทดลองเป็น dead-end)

### หน้า D — ฟอร์ม → ContactLead
งานนี้อยู่ใน roadmap.py เฟส 9 แล้ว ("ต่อฟอร์ม lead ทุกหน้าเข้า ContactLead + honeypot", status TODO) — ไม่ใช่งานใหม่ที่ต้องบรีฟซ้ำ ใช้สเปกจาก `queueflow_salepage_structure.md` หัวข้อ 4.1 (ฟิลด์ที่ต้องแก้, `email` ต้อง blank=True, thank-you inline pattern จาก V4 ไม่ใช่ V4 ทั้งไฟล์)

## 3. เรื่องที่ต้องให้เจ้าของเคาะก่อนทีมเขียนหน้าจริง (DECISION ใหม่ที่ควรเข้า roadmap.py)

1. **โครงสร้างราคา** — message.md เสนอเปลี่ยนจาก "setup+รายเดือน" เป็น "ขายขาด 3 tier ฿12,900/19,900/29,900 + ค่าดูแลสมัครใจปีที่ 2" ซึ่งเป็นคนละมติกับที่ Money Manager อนุมัติแล้วในเฟส 5 (฿9,900+฿990 ฯลฯ) **ห้ามขึ้นหน้าขายจริงจนกว่า Money Manager จะเคาะใหม่อีกรอบ** — ระหว่างนี้ V5 หน้า B ใช้ราคาเดิมที่อนุมัติแล้วไปก่อน
2. **แบรนด์คู่แข่งบนหน้าเว็บ** — ทั้งสองเอกสารมีข้อห้ามชัดอยู่แล้ว (ห้ามเคลม Fresha แพง, ห้ามพาดพิง GoWabi ตรงๆ) ต้องให้ `legal-advisor` ตรวจ wording ก่อน publish ทุกประโยคที่พาดพิงคู่แข่ง — ยังไม่ได้ทำ
3. **หน้าขาย POS** — ตามที่เจ้าของสั่ง "POS เสร็จแล้ว live แล้วแต่ไม่มีใครรู้" `queueflow_salepage_structure.md` หัวข้อ 5 มีสเปกแม่แบบไว้แล้ว (ใช้โครงเดียวกับ QueueFlow ได้ 85%) แต่ต้องรอ `market-research-analyst` ทำคู่แข่ง POS ไทยก่อน (ยังไม่ทำ) และต้องมี screenshot ระบบจริง 3-5 ภาพก่อนเขียน section ของจริง — **นี่คือคอขวดตัวจริงของหน้า POS ไม่ใช่การเขียน copy**
