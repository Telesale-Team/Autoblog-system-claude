📘 Guide 01 · คู่มือการทำงาน

ย้ายทีมหนูดี ไปทำงานโปรเจกต์ใหม่
ต้องขนอะไรไปบ้าง?

สร้างโฟลเดอร์ใหม่ขึ้นมาแล้วอยากให้หนูดีกับทีม Agent ทั้ง 25 ตัวตามไปทำงานด้วย — คู่มือนี้จะพาดูว่า "ตัวตน" ของทีมอยู่ตรงไหน ก๊อปอะไร และกับดักเรื่องความจำที่คนมักพลาด

อ่าน: ~6 นาที ระดับ: เริ่มต้น อัปเดต: มิ.ย. 2026
ในหน้านี้
ทำความเข้าใจก่อน 1. ทีมงานอยู่ตรงไหน 2. กับดักเรื่องความจำ 3. เลือกวิธีย้าย 4. ลงมือทำ (ทีมสะอาด) 5. 3 จุดที่ต้องแก้ สรุป & Checklist

หลายครั้งเวลาเราเริ่มงานชิ้นใหม่ เราอยากแยกมันออกมาเป็นโฟลเดอร์ของตัวเอง ไม่ปนกับงานเก่า แต่พอแยกออกมาแล้ว... หนูดีกับทีม Agent ก็หายไปด้วย เพราะ Claude Code มองว่า "โฟลเดอร์ใหม่ = โปรเจกต์ใหม่ = ไม่รู้จักทีมนี้"

📦

ลองคิดว่าทีม Agent เหมือน ทีมงานที่กำลังจะย้ายออฟฟิศ — เราไม่ได้ย้ายแค่ "ตัวคน" แต่ต้องขน คู่มือการทำงาน (ความสามารถ) และ แฟ้มความทรงจำ (สิ่งที่ทีมเคยเรียนรู้) ไปด้วย ถ้าลืมขนอย่างใดอย่างหนึ่ง ทีมก็ทำงานได้ไม่เต็มที่

คู่มือนี้จะพาไล่ดูทีละขั้น ว่า "ตัวตน" ของทีมจริง ๆ เก็บอยู่ที่ไหน, มีกับดักอะไรที่ทำให้ความจำหาย, และวิธีย้ายที่ถูกต้องสำหรับการ "เริ่มทีมใหม่สะอาด ๆ"

1ทีมงานอยู่ตรงไหนกันแน่?

ก่อนจะขนของ ต้องรู้ก่อนว่าของอยู่ที่ไหน

สิ่งที่ทำให้หนูดี "เป็นหนูดี" และทำให้ Agent ทั้ง 25 ตัวมีตัวตน จริง ๆ แล้วเก็บอยู่แค่ 2 ที่ เท่านั้น — และน่าแปลกใจที่ หนึ่งในนั้นอยู่นอกโฟลเดอร์โปรเจกต์

แปลเป็นภาษาคน

  • .claude/agents/ — คือ "ตัวคน" ทั้ง 25 Agent แต่ละไฟล์คือสมองของ Agent หนึ่งตัว
  • .claude/skills/ — คือ "ทักษะ" ที่หยิบมาใช้ซ้ำได้ เช่น ทำไดอะแกรม, เขียน blog
  • .claude/settings.json + startup_hook.py — กฎและพิธีเปิดงาน (เช่น สั่งให้อ่าน memory ก่อนเริ่มทุกครั้ง)
  • CLAUDE.md — คู่มือเล่มใหญ่ บอกว่าใครทำอะไร และเวลามีงานเข้าให้ส่งต่อให้ใคร
  • memory/ — สมุดบันทึกความทรงจำ ที่หนูดีจดสิ่งที่เรียนรู้ไว้ข้ามวันข้ามครั้ง

2กับดักเรื่องความจำ (จุดที่คนพลาดบ่อยที่สุด)

ทำไมก๊อปทุกอย่างแล้วหนูดียัง "ความจำหาย"

นี่คือหัวใจของคู่มือทั้งหน้านี้เลยครับ Claude Code ไม่ได้เก็บโฟลเดอร์ memory/ ไว้ในโปรเจกต์ แต่เก็บไว้ที่ส่วนกลางของเครื่อง แล้ว ตั้งชื่อโฟลเดอร์ตาม path ของโปรเจกต์

💡

ข่าวดีสำหรับ "ทีมสะอาด"ถ้าเราตั้งใจจะ เริ่มใหม่จากศูนย์ อยู่แล้ว กับดักนี้กลายเป็น ของแถม ทันที — เพราะ Claude Code จะสร้างโฟลเดอร์ memory ว่าง ๆ ให้เราเองโดยอัตโนมัติ เราจึง ไม่ต้องก๊อป memory/ เลย

3เลือกวิธีย้าย — มี 3 แบบ

ก๊อปไม่เหมือนกัน ขึ้นอยู่กับว่าโปรเจกต์ใหม่ทำอะไร

★ คู่มือนี้

ทีมสะอาด

เอาแค่โครงทีม 25 Agent ไปเริ่มงานคนละแบบ ความจำเริ่มจาก 0

เหมาะกับ: งานใหม่ที่ไม่เกี่ยวกับ Django/blog เดิม
ตัวเลือก B

Clone ทั้งระบบ

ยกระบบธุรกิจทั้งก้อน (blog, dashboard, calendar) ไปด้วย

เหมาะกับ: ทำสาขา/แบรนด์ใหม่บนระบบเดิม → ใช้ git clone
ตัวเลือก C

ทีม + ความจำบางส่วน

เอาโครงทีมไป แต่หยิบ memory เฉพาะ "วิธีการทำงาน" ติดไปด้วย

เหมาะกับ: อยากให้ทีมจำสไตล์การทำงาน แต่ลืมเรื่องธุรกิจเดิม
🧭

คู่มือนี้โฟกัสที่ "ทีมสะอาด"เป็นแบบที่ใช้บ่อยที่สุดและปลอดภัยที่สุด ส่วนแบบ Clone และ Hybrid จะแยกเป็น Guide ต่อไปครับ

4ลงมือทำ — เริ่มทีมใหม่สะอาด ๆ

4 ขั้นตอน จากโฟลเดอร์ว่างสู่ทีมพร้อมทำงาน

1

ก๊อป .claude/ ไปทั้งโฟลเดอร์

นี่คือ "สมองและทักษะ" ของทีมทั้งหมด ก๊อปยกโฟลเดอร์ไปวางในโปรเจกต์ใหม่ได้เลย

# จากในโฟลเดอร์โปรเจกต์เดิม
cp -r .claude/ "path/ไปยัง/My-New-Project/"
2

ก๊อป CLAUDE.md ไปด้วย

คู่มือ routing ของทีม — แต่เดี๋ยวเราจะต้องแก้เนื้อหาในขั้นที่ 5 เพราะตอนนี้มันเต็มไปด้วยเรื่องธุรกิจเดิม

cp CLAUDE.md "path/ไปยัง/My-New-Project/"
3

เลือก skill ที่จำเป็น (ไม่ต้องเอาทั้ง 12)

skill บางตัวผูกกับระบบ Django blog เดิม ถ้างานใหม่ไม่เกี่ยวก็ลบทิ้งได้ ดูรายละเอียดในขั้นที่ 5

4

เปิด Claude Code ในโฟลเดอร์ใหม่ — จบ!

Claude Code จะสร้างโฟลเดอร์ memory/ ว่าง ๆ ให้เองอัตโนมัติ ได้ทีมสะอาดพร้อมเริ่มงานทันที

🚫

ไม่ต้องก๊อป 2 อย่างนี้settings.local.json (เป็น permission สะสมของเครื่องเดิม ปล่อยให้สร้างใหม่ดีกว่า) และ memory/ (ปล่อยให้เริ่มว่าง ๆ ตามที่อธิบายในข้อ 2)

53 จุดที่ "ต้องแก้" หลังก๊อป

ไม่แก้แล้วทีมจะทำงานเพี้ยน เพราะยังชี้กลับไปของเดิม

① startup_hook.py — path ฝังตายตัว

ไฟล์นี้มี path เต็ม ๆ ชี้กลับไป memory ของโปรเจกต์เดิม ต้องเปลี่ยนให้ตรงโปรเจกต์ใหม่ หรือถ้ายังไม่อยากใช้ระบบ memory ก็ลบ hook นี้ทิ้งไปก่อนได้

# ในไฟล์ .claude/startup_hook.py — แก้บรรทัดที่ชี้ path
# เดิม: ...\E--Project-Peyo-Peyo-...\memory\MEMORY.md
# ใหม่: ...\E--My-New-Project\memory\MEMORY.md

② CLAUDE.md — ลบเรื่องธุรกิจเดิมออก

ตอนนี้เต็มไปด้วยรายละเอียดเฉพาะ (สินค้า AI, Django port 8000, deploy server, content backlog) ให้เก็บไว้แค่โครงที่ใช้ซ้ำได้ แล้วเขียนส่วนที่เหลือใหม่ให้ตรงงานใหม่

  • เก็บไว้: ตาราง 25 Agents, วิธี activate, routing logic, approval matrix
  • ลบ/เขียนใหม่: สินค้าและบริการ, deploy workflow, content backlog, ตัวเลขธุรกิจ

③ settings.json — เคลียร์ path เฉพาะเครื่อง

มี additionalDirectories ที่ชี้ไป static ของโปรเจกต์เดิม ลบออกหรือแก้ให้ตรงโปรเจกต์ใหม่

⚠️

skill 4 ตัวนี้ผูกกับ Djangoถ้าโปรเจกต์ใหม่ไม่มีระบบ blog พวกนี้จะใช้ไม่ได้: django-blog-publisher, diagram-to-blog และ skill ที่อ้าง Calendar API localhost:8000 ในโปรโตคอลเปิดงาน — ถ้างานใหม่ไม่เกี่ยวกับ blog แนะนำไม่ต้องก๊อป skill กลุ่มนี้

สรุป & Checklist

เช็กให้ครบก่อนเริ่มงานในโปรเจกต์ใหม่

  • ก๊อป .claude/ (agents + skills + settings.json + startup_hook.py)
  • ก๊อป CLAUDE.md
  • เลือก skill เท่าที่จำเป็น ลบตัวที่ผูกกับ Django ถ้าไม่ใช้
  • แก้ path ใน startup_hook.py (หรือลบ hook ทิ้ง)
  • เขียน CLAUDE.md ใหม่ให้ตรงงานใหม่ เก็บแค่โครงทีม
  • ลบ additionalDirectories เก่าใน settings.json
  • อย่าก๊อป memory/ และ settings.local.json — ปล่อยให้สร้างใหม่
อยากให้หนูดีทำให้

บอก path โฟลเดอร์ใหม่ + งานใหม่ทำเกี่ยวกับอะไร

เดี๋ยวหนูดีจัดให้ครบในทีเดียว — ก๊อปไฟล์, แก้ path, ร่าง CLAUDE.md ใหม่ให้ตรงงาน แค่พิมพ์บอกมาได้เลยครับ 🐾
